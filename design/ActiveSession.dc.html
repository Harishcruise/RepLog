Active session — the core loop
Route /app/workout/[id]. "Log a set in ~2 taps" drives every choice here. Pushed/immersive like Profile and Body — no floating nav, no tab bar, no contextual pill (its job is getting you back here — redundant once you're already here). Its own sticky header replaces that chrome.
Set row — 5 columns, not 6
SET · PREV · KG · REPS · ✓. RPE dropped from the earlier Components.dc.html sketch — opt-in-by-habit for most lifters, not worth a permanent column on every row. The SET badge is tappable → the set-type picker (frame 5), replacing the old "W badge + red-dot" per-type styling with one consistent interaction.
Set-type picker — the full loop (frame 5)
Tap the SET badge (drawn 22px, tap target padded to ~40px) → a popover anchors right below it — not a detached corner box, flips above if the row's near the bottom of the screen. Four options, current selection checked; tap one and it applies immediately, popover closes — no confirm step. Tap outside to dismiss with no change.

Badge feedback: stays showing the set number always (you're scanning "which set" constantly) — the ring/fill just tints per type (Incline DB Press card, this frame: 1 amber-Warmup, 3 violet-Drop set, 4 red-Failure). Normal stays the plain gray badge.

Retroactive: the badge stays tappable even on a completed/collapsed row — re-tag a set after the fact without reopening anything else.

Defaults: every new set starts Normal regardless of the previous set's type — explicit tagging only, no silent carry-over that could mislabel data.

Scope for v1: type is a tag, not a different data-entry shape. A drop set is still one row with one weight/reps pair — an actual mid-set weight drop is a second row you add and tag yourself. Warmup sets are excluded from volume/PR stats behind the scenes; the row itself looks the same as any other.
Ghost placeholders
An un-logged set's KG/REPS cells show last time's numbers as muted ghost text (frame 1, set 3 on each card) instead of blank — tap ✓ to confirm as-is with zero typing if you're repeating the same numbers, or tap the cell to open the keypad and change it.
Completed rows quiet down, but stay column-honest
First pass highlighted every finished row with a green tint — with 3-5 sets per exercise that meant most of the card fighting for attention. Second pass merged the logged value into one line of text, but it started at the PREV column's position and read as "PREV: 100 kg × 8" — misleading, since it's the number you actually logged. Now: values stay under their real KG/REPS headers, PREV shows a quiet "—" (irrelevant once you're done), just de-emphasized — muted text, no fill, a small check instead of the toggle. Whole row stays tappable to reopen it, no time limit.
Undo has two doors (frame 4)
Tapping ✓ by accident mid-set shouldn't need precision to fix. An instant "Set logged · Undo" toast fires right away for fast recovery — and separately, the collapsed row itself stays tappable forever to reopen and re-edit, so missing the toast's window costs nothing.
Docked numeric keypad (frames 2-3)
Tapping a KG/REPS cell docks this instead of the OS keyboard — predictable height, never covers the row above it, ring-highlights the focused cell. Sidesteps OS-keyboard-covers-input entirely, the same class of problem Profile's dialogs avoid by not being a bottom sheet.
Digit keys and Save got a pass for contrast
Both were flat-filled the same gray as the panel behind them — dull, and Save was indistinguishable from a plain digit at a glance. Digits now sit a shade lighter with a hairline border so they read as physical keys. Save keeps the same quiet fill (still a utility action, not a milestone) but picks up a green-tinted border — enough to mark it as the one key that does something different, without promoting it to the primary green the header buttons use.
Two different jobs, not one button doing double duty
The grid's big bottom-right button (same reachable spot on both steps) always means the same thing regardless of field: Save — commit whatever's typed and close the keypad, no other side effects. Quiet gray, not the tinted-green pill, since it's a plain utility action.

The header buttons carry the deliberate, forward-moving actions and share the tinted-green primary treatment: Next: Reps → (frame 2) chains into editing reps next; Log set (frame 3) is the one that actually completes the set (checks it off, starts rest) — tapping grid-Save on the same screen would just save the rep count and close, leaving the set unchecked for later. ← Back: KG sits next to Log set but in the same neutral secondary color as the app's Secondary button (Components.dc.html) — it's a correction, not a milestone, so it shouldn't compete visually with the action that's actually finishing the set.
Rest pill reuses the nav's real estate (frame 4)
Same floating-pill treatment as the Resume pill elsewhere in the app, in the exact bottom slot the nav shell would occupy if it were showing — which it isn't here, so that space is free. Auto-starts on ✓, tap → expands to the sheet already speced in Components.dc.html (−15s/+15s, target rest, Skip). Fires a local notification + short vibration at 0.
Not covered here: reorder (drag handle) and swipe-to-delete on set rows — both interaction-only, nothing new to draw statically. Session Finish → Summary screen (duration, volume, PRs, muscles worked) is a separate screen, not part of this one.
