Profile
Route /app/profile, opened from the Home header avatar (not a tab, so it gets a back link instead of living in the floating nav). One screen — merges what would otherwise be a separate Settings screen, since v1's settings list is short.
One dialog shell for every edit (frames 2–3)
Single reusable shadcn Dialog (Radix): centred card, close-X, title, field(s), one primary action. Used for change password (frame 2), default rest (frame 3, preset chips instead of a stepper), and — same shell, not redrawn here to avoid redundant frames — name (single text field) and avatar colour (swatch grid instead of a text field). One interaction language for every edit on this screen, not five.
Dialog over bottom sheet — mobile keyboard
First pass used a bottom sheet. Changed: a sheet pinned to the bottom edge sits exactly where the mobile keyboard rises from — the field you're actively typing into (new password, name) can end up hidden behind it. A centred dialog isn't anchored to that edge, so there's real buffer before the keyboard reaches it; for a short 2-field form that's enough to stay clear. Selection-only content (rest chips, avatar swatches) doesn't need a keyboard at all, but uses the same dialog anyway — one shell, not two.
Units stays instant, not a dialog
The one deliberate exception: units is true direct manipulation — tap "lb", it's already done, nothing to confirm. It isn't a form, so opening a dialog for it would add a step without buying anything. Everything that is a form (needs a value entered/chosen, then confirmed) uses the dialog; the one thing that isn't, doesn't.
Sets up a shared modal vocabulary
Not a one-off for Profile — UX.md's session-discard confirmation will want AlertDialog, a sibling of this same Radix family. The exercise picker and rest-timer expand stay as sheets (established separately, and both are full-height browsing/selection UI where a sheet is the right call) — this doesn't change that, it just means the app ends up with two deliberate, distinct modal patterns instead of an accidental third.
Stats strip — stubbed
Streak / sessions / kg lifted shown with plausible sample values. Wired the same way as the nav shell's session state: a stub hook returning placeholder data until workout_sessions exists (SPEC.md milestone 2), swapped for a real query with no UI changes needed.
Reuses existing auth plumbing
"Change password" calls updatePassword — the exact op built for /login/reset's last step. It works on any authenticated session, not just a recovery one, so no new auth logic is needed here — just a new caller.
Identity
Avatar is initials + colour only, no photo upload (matches SPEC.md keeping photo/media handling out of v1) — one new profiles.avatar_color column. Name pulls from user_metadata.display_name; email and "member since" are read-only, straight off auth.users. No in-app email change in v1 — that needs its own re-verification flow.
Bodyweight log row → /app/body (its own screen — chart + daily entry, doesn't belong in a sheet). Sign out reuses the existing SignOutButton logic.
