Profile
Route /app/profile, opened from the Home header avatar (not a tab, so it gets a back link instead of living in the floating nav). One screen — merges what would otherwise be a separate Settings screen, since v1's settings list is short.
Stats strip — stubbed
Streak / sessions / kg lifted shown with plausible sample values for the mockup. Wired the same way as the nav shell's session state: a stub hook returning placeholder data until workout_sessions exists (SPEC.md milestone 2), swapped for a real query with no UI changes needed.
Inline tap-to-edit
Units — the segmented control itself is the edit; tapping "lb" switches immediately, no confirm step. Default rest — tapping the row opens an inline stepper (not shown as a separate frame; same pattern as password below). Change password — frame 2: tapping the row expands it in place to two fields + Save, chevron rotates 90° as the open-state affordance. No new route for any of these.
Name + avatar edit (frame 3)
Both were missing from the first pass — added per feedback. Name: a pencil icon next to it (frame 1) is the discoverability hint; tapping turns the name into an inline input in place, checkmark confirms. Avatar: a small pencil badge on the circle (frame 1) hints it's tappable; tapping reveals a row of preset colour swatches below it, volt stays the default. Colour only, no photo upload — one new profiles.avatar_color column, no Storage bucket/cropping/upload UI. Both trigger independently, same "no new route" rule as everything else on this screen.
Reuses existing auth plumbing
"Change password" calls updatePassword — the exact op built for /login/reset's last step. It works on any authenticated session, not just a recovery one, so no new auth logic is needed here — just a new caller.
Identity
Avatar is initials-only, no photo upload (matches SPEC.md keeping photo/media handling out of v1). Name pulls from user_metadata.display_name (set at signup); email and "member since" are read-only, straight off auth.users. No in-app email change in v1 — that needs its own re-verification flow.
Bodyweight log row → /app/body (its own screen — chart + daily entry, doesn't belong inline here). Sign out reuses the existing SignOutButton logic.
