Navigation shell — floating
Same structure as before (contextual bar + 4-tab bar), new treatment: both are inset ~14px from the screen edges, fully rounded, elevated with a soft shadow — floating above the content instead of docked flush to the bottom edge.
Why floating over docked
Every other surface in the system (cards, popovers, OTP boxes) is an inset rounded shape on the obsidian ground. A bar flush to the screen edge was the one exception. Floating also reads correctly at any viewport — the app is a centred ≤480px column everywhere (DESIGN_SYSTEM.md §5), so a bar flush to the column's edges implies a phone chassis that isn't there on web. A floating bar makes no such claim.
Tab labels — icon-only, active expands
Supersedes "icons + text always shown." Inactive tabs are icon-only circles on a subtle lighter fill; the active tab grows to fill the remaining tray width as a solid volt pill with icon + label. The label now confirms where you are rather than helping you decide where to go — you already tapped it. Real build: animate the width/position change (Framer Motion layoutId or an equivalent shared-layout transition) so it morphs instead of jump-cutting.
Other changes from the docked version
  • Content needs a bottom fade + ~150px scroll padding so it doesn't hard-cut under the floating stack.
  • backdrop-filter: blur on the tab pill so content peeking through the gap between the two pills still feels like one system.
Unchanged
Still exactly 4 tabs (Home · History · Exercises · Progress), still no FAB, still one contextual pill that swaps Start ⇄ Resume state and survives tab navigation (frame 2 shown from the Progress tab).
